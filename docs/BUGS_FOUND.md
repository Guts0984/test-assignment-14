# Bugs found by tests

| # | Attack / scenario | Impact | Root cause | Fix | Test |
| --- | --- | --- | --- | --- | --- |
| 1 | Deeply nested JSON body (`[` x 100 000 or 20 000 nested objects) | HTTP 500 "Internal error" from a body-parser stack overflow instead of a clear client error (violates INV-15) | The `RangeError` raised by `JSON.parse` is not a `SyntaxError`, so body-parser did not map it to a 400 and the error middleware treated it as unexpected | `toErrorBody` maps the stack-overflow `RangeError` to `400 VALIDATION_FAILED` | `apps/api/test/adversarial/input.adv.test.ts` (deeply nested JSON) |
| 2 | Hold request with a seat id of 2^53 (`9007199254740992`) | Passed validation (`int()`), silently lost precision and was looked up as another seat id; answered 409 instead of 400 | `z.number().int()` accepts integers beyond `Number.MAX_SAFE_INTEGER` | Shared `seatIdSchema` = `int().safe().positive()` used by every seat-id field | `apps/api/test/adversarial/input.adv.test.ts` (hold requests with SQL, floats, ...) |
| 3 | Payment arrives after the places were taken (acceptance 7b) | The automatic full refund task failed 8 times and the order stayed `expired`; money was in but never returned | Marking the order `refunded` violated `CHECK (status ... paid_at IS NOT NULL)` because a refunded-before-paid order had no `paid_at` | `paid_at` is set when the payment is received, regardless of whether tickets follow | `apps/api/test/adversarial/payments-flow.adv.test.ts` (someone else took the places) |
| 4 | Hold expires while the owner has the event page open (found by the real-browser e2e) | The owner's page kept showing the lapsed hold as "in your order" until a reload; only other viewers' seat maps were updated | The worker's expiry sweep released the order and notified the event room, but never sent `order.updated` to the owner; the web "my orders" list also ignored that event | The sweep now emits `order.updated` (status `expired`) to the owner exactly once per released order; `useMyOrders` refreshes on `order.updated` | `apps/worker/test/sweep.int.test.ts`, `apps/web/e2e/hold-expiry.spec.ts` |
| 5 | Checkout in the compose test profile reported "provider busy" for every order (found by the real-browser e2e) | Not a code bug in the product: nginx runs on the host network in the test profile, so containers could not resolve `nginx` for `PAYMENT_PROVIDER_URL`. Left as a record because the symptom (all payments failing) is easy to misread | Profile wiring | The test profile points the api and worker at `http://api-1:3001/stub` | `apps/web/e2e/purchase-journey.spec.ts` |
